# Current rendering stack

## Decision

Project Toolpath uses two deliberately separate rendering layers:

1. Canvas 2D and DOM/SVG for high-frequency simulation, telemetry, G-code, and accessible controls.
2. A dependency-free binary GLB inspector for authored `.glb` smoke tests, with a deliberate adapter point for a production WebGL engine when the modular kit begins.

This avoids rewriting the deterministic gameplay renderer while establishing a production-grade Blender-to-browser asset path. The first integration surface is `/lab/asset-pipeline`. It loads both the canonical smoke test and the five-asset capability kit described by `/assets/manifests/machine-capability-kit.json`.

## Existing surfaces

| Surface | Renderer | Purpose |
| --- | --- | --- |
| Manual campaign | Canvas 2D | Interactive machining grid and rapid feedback |
| G-code stage | DOM/ASCII | Code-first visualization and social-friendly output |
| Part previews | CSS/SVG | Lightweight silhouettes and diagrams |
| Asset pipeline lab | Binary GLB parser + Canvas 2D software projection | GLB validation, geometry decoding, framing, and interaction |

## Asset contract

- Source files live under `assets-src/blender/`.
- Reproducible Blender scripts live under `tools/blender/`.
- Runtime GLB files live under `public/assets/<category>/`.
- Models use metric units, centered origins, applied transforms, meaningful object names, and Y-up GLB export.
- The smoke test must contain exactly one named mesh object and one material.
- Each first-generation machine archetype exports as one named mesh, one material, and one primitive so it remains inexpensive to validate and display.
- The smoke-test gate passed before the capability kit was generated.
- Machine archetypes communicate process families only; they cannot contain manufacturers, models, controllers, quantities, locations, identifiers, network details, or claims about actual inventory.

## Reproduction

1. Run `tools/blender/start-local-mcp.ps1` in one terminal.
2. Send `tools/blender/create_toolpath_test_asset.py` through the configured MCP client. For a deterministic command-line fallback, run `tools/blender/export-test-asset.ps1`.
3. Start the application and open `/lab/asset-pipeline`.

The lab reads vertex and index buffers from the actual GLB; it is not a screenshot or a hard-coded cube. This keeps the initial proof small and deployable without adding a large renderer before production asset requirements are known.

The local Blender profile is generated under `tools/blender/runtime/` and is intentionally ignored by Git.

## Capability kit

The reproducible source is `assets-src/blender/toolpath-machine-kit.blend`, generated by `tools/blender/create_machine_kit.py`. It exports:

- foundation manual mill;
- vertical three-axis machining cell;
- trunnion five-axis machining cell;
- horizontal turning cell;
- wire EDM cell.

These are fictional silhouettes intended for training navigation and process literacy. They are not digital twins and must not be presented as representations of a specific facility.
